# StrucTab 复现：实现来源与改动台账

本文档持续记录每个阶段与官方仓库的关系，回答三个问题：复用了什么、没有复用什么、
自行实现了什么。后续每完成一个 Phase，都在本文档末尾追加对应章节，不改写历史结论。

## 分类口径

| 类型 | 含义 |
|---|---|
| 直接复用 | 运行官方代码、模型、数据或协议；不自行重写核心语义 |
| 参考后重写 | 阅读并保持官方语义，但为了本项目接口、规模或可靠性重新实现 |
| 明确未采用 | 已评估官方方案，但因硬编码、硬件规模或任务不匹配而不使用 |
| 自行实现 | 官方仓库没有可直接满足当前需求的实现，由本项目新增 |
| 官方源码修复 | 直接修改官方源码中的确定性 bug，并保留回归测试和 debug 记录 |
| 保留官方行为 | 已识别官方边界或潜在问题，但缺乏论文依据时不做推断性修改 |

## 阶段完成时的同步规则

每个 Phase 收尾时至少执行以下检查：

1. 更新 `reproduction/README.md`：状态、入口命令、主要产物和测试总数。
2. 更新 `doc/实验结果.md`：如果产生正式可比实验结果，填写总表、分层表和 failure
   cases；若本阶段没有评测结果，明确记录“不产生可比指标”。
3. 更新本文档：追加直接复用、参考后重写、明确未采用、自行实现和源码修复情况。
4. 更新 `doc/实现计划.md` 中对应 Phase 的完成状态和验收证据。
5. 如果发现或修复 bug，同步更新 `doc/debug记录.md`。
6. 只有固定评测集全部完成后才填写正式指标，不能用局部运行结果占位。
