## Phase 11：mini RL 的 Go/No-Go 决策

> 状态（2026-08-29）：**已完成决策，No-Go**。不执行 mini RL 探针，也不启动 RL
> optimization。该结论针对当前 8GB RTX 4060 Laptop + WSL 环境和本项目现有 checkpoint
> 状态，不解释为算法在其他硬件上不可运行。

Go 条件：

- SFT 模型能在可控显存下生成多个 rollout
- GRPO 框架支持当前 HunyuanOCR 架构
- policy、reference/anchor 和 reward 服务能合理调度
- 单步时间仍具备实验价值

实际判定：已存在足以否决的前置条件，因而不再额外验证 GRPO 架构兼容性。

- Phase 7/8 正式训练被硬件阻塞，没有可用的正式 Stage 2 checkpoint；
- Phase 9 按项目决定只完成 SFT 数据，没有 SFT checkpoint；
- 更轻的单样本全参数 Stage 2 soak 已出现 WSL/DXG residency 失败；
- RL 还需 policy 训练、多个 rollout、Anchor OCR 与 reward 服务协同，资源压力高于已失败负载；
- 用 LoRA mini RL 不能补齐缺失的论文对齐前置 checkpoint，也不能表述为论文路线结果。

因此项目正式停止在：

```text
完整的数据/SFT/RL split 构造 + 完整 Uni-TabRL reward analysis
```

`reproduction/data/splits/rl.jsonl` 仍作为已固定的数据方法产物保留，但没有被用于训练。
不能把 reward evaluation 表述为 RL training，也不产生 RL checkpoint 或效果指标。
